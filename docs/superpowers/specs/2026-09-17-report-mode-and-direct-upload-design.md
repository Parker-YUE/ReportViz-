# ReportViz 评分模式与 10MB 安全直传设计

日期：2026-09-17

## 目标

在不改变现有普通报告生成体验的前提下：

1. 增加“普通版 / 五维评分版”选择，默认普通版。
2. 五维评分版必须输出综合评分、五维雷达图、五个维度分数和判断依据。
3. 原文件中的评分维度优先保留；不足五维时补足；没有维度时按报告内容生成；AI 转型固定五维只作为无原文规则时的兜底。
4. 文件上传上限从 3MB 提升到 10MB，避开 Vercel Function 4.5MB 请求体限制。
5. 首页始终展示联系方式：`咨询及合作｜微信：allen20255`。
6. 核心流程兼容 Windows Edge/Chrome、macOS Safari/Chrome、iPhone Safari 和 Android Chrome。

## 用户界面

### 报告版本

在“AI 智能生成”按钮上方放置两个互斥选择卡：

- 普通版（默认）：适合会议纪要、项目总结、复盘记录等，不强制评分。
- 五维评分版：适合调研报告、人才评估、能力诊断、职业规划等需要判断和打分的文件。

五维评分版备注：

> 会议纪要、纯记录类文件通常不需要评分，建议选择普通版。

普通版保持现有行为。五维评分版的生成图片必须包含综合评分、五维雷达图、五个维度分数和判断依据。

### 上传进度

文件模式改为两阶段进度：

1. 文件安全上传中。
2. AI 分析中。

粘贴文字仍直接进入 AI 分析，不经过 Storage 直传。

### 联系方式

全局顶部导航增加弱强调文字：

`咨询及合作｜微信：allen20255`

导航位于登录页和主功能页之外，因此两种页面状态都能看到联系方式。移动端允许换行，但不得遮挡 Logo 或版本号。

### 跨平台兼容

- Windows 与 macOS 桌面浏览器均能完成登录、选择报告版本、上传、生成、查看和下载。
- iPhone Safari 与 Android Chrome 在常见手机宽度下保持按钮可点击、文字不溢出、卡片不重叠。
- 直传使用这些浏览器共同支持的标准浏览器能力，不依赖桌面端专属 API。
- 视觉增强允许在旧版浏览器降级，但登录、上传、生成、查看和下载等核心功能不得失效。

## 五维评分规则

评分版使用以下优先级：

1. 原文明确给出五个维度：保留原文维度名称和含义。
2. 原文给出一至四个维度：保留已有维度，由 AI 根据全文补足到五个。
3. 原文没有维度：AI 根据报告类型动态生成最匹配的五个维度。
4. 仅当报告属于 AI 转型且原文没有自带维度时，使用现有固定五维：行业适配度、能力迁移、学习能力、行业资源、风险评估。

继续执行现有评分纪律：

- 综合评分和维度评分不得低于 70。
- 同一内容重复生成时，综合评分相对历史结果最多波动 ±3。
- 综合评分应与五个维度分数逻辑一致。

请求新增 `report_mode`：

- `standard`：普通版，默认值，用于兼容旧页面和旧调用。
- `scored`：五维评分版。

其他值返回 HTTP 400。

评分版结果在保存前必须校验：存在 `radar_score`、维度恰好五项、每项包含名称、有效分数和非空判断依据。校验失败时返回清晰错误和 `request_id`，不静默伪造五维结果。

## 10MB 文件直传架构

### 选择

采用 Supabase private Storage 签名直传。不能只提高前端数字，因为 10MB 文件经 Base64 后约为 13.3MB，会超过 Vercel Function 4.5MB 请求体上限。

### 数据流

1. 用户选择 PDF、DOCX 或 TXT，前端先检查扩展名和 10MB 上限。
2. 前端携带用户令牌调用 `POST /api/upload-ticket`，只提交文件名、大小和 MIME，不提交文件内容。
3. 后端验证邀请码、频率、扩展名、大小和 MIME，生成随机 UUID 记录 ID及 Storage 路径。
4. 后端使用 Supabase Service Key 创建单路径签名上传地址，并签发短期 `upload_ticket`。Service Key 永不返回浏览器。
5. 浏览器通过 HTTPS 将文件直接上传到签名地址。
6. 前端调用 `/api/parse`，提交 `upload_ticket` 和 `report_mode`。
7. `/api/parse` 验证上传票据与当前邀请码一致，从 private bucket 下载文件，再次检查实际字节数、扩展名和文件特征。
8. 解析成功后，以预生成 UUID 写入 `parse_records`，原文件已位于该记录对应的私有路径，无需再次上传。
9. 解析失败时删除本次上传文件；浏览器中断产生的无记录孤立文件保持私有，并受每个邀请码的签发频率和 10MB bucket 限制约束。后续如数量明显增加，再单独设计定时清理，不在本次引入 Cron 或新环境变量。

### 兼容性

- 新页面统一走签名直传。
- `/api/parse` 暂时保留现有 Base64 入参，继续限制原文件最大 3MB，用于旧客户端兼容。
- 文本粘贴流程保持不变。
- 数据库 schema 不变；`parse_records.id` 已支持显式 UUID。
- 后台原文件下载继续使用 `{recordId}/input`，接口无需改变。

## 安全控制

- `attachments` bucket 保持 private。
- Service Key 只在服务端使用，不进入响应、日志或前端代码。
- 签名上传只允许一个随机路径，禁止客户端指定路径和覆盖已有对象。
- `upload_ticket` 使用现有 JWT Secret 签名，绑定邀请码、记录 ID、路径、文件名、声明大小和过期时间。
- 解析时要求用户令牌邀请码与 `upload_ticket` 完全一致。
- 签名 URL、上传 token、用户 token 不写入日志。
- 前端、签发接口、Storage bucket 和解析接口执行分层大小检查。
- PDF 检查 `%PDF` 文件头；DOCX 检查 ZIP/Office 容器；TXT 拒绝明显二进制内容并沿用 UTF-8/GB18030 解码。
- 文件名只作为显示信息，Storage 路径完全由服务端生成。
- 上传票据接口纳入现有每日调用限制，避免批量占用 Storage。
- 上传内容只按 PDF、DOCX、TXT 数据处理，Storage 保持私有，不提供可执行文件托管能力。
- 原文件下载强制使用附件下载语义，不以内联网页内容执行。
- AI 结果和后台动态内容进入页面前必须经过安全转义，禁止把不可信内容直接拼入可执行 HTML。
- API Key、Service Key、JWT Secret 仅从服务端环境变量读取，不进入前端包、API 响应、日志或版本库。
- 上线前执行依赖高危漏洞检查、敏感信息扫描和关键接口安全复核；发现高危问题不得部署。
- 安全目标是分层降低攻击和泄露风险，不作“绝对不会被攻击”的虚假承诺。

## Supabase Storage 配置

经用户明确授权，部署时将 `attachments` bucket 调整为：

- private：保持不变。
- file size limit：10MB。
- allowed MIME types：PDF、DOCX、TXT、PNG 对应 MIME。

该变更不修改数据库表结构，也不新增环境变量。

## 代码边界

- `public/index.html`：模式选择卡、说明文字、联系方式、直传和进度状态。
- `api/upload-ticket.js`：签名上传票据接口。
- `api/parse.js`：模式校验、上传票据解析、Storage 文件读取、评分版结果校验。
- `lib/storage.js`：创建签名上传地址、读取和删除指定上传对象。
- `lib/upload-validation.js`：10MB Storage 文件验证与文件特征检查；旧 Base64 仍保持 3MB。
- `lib/result-sanitizer.js`：评分模式、原文维度优先级、五维结果校验。
- `prompts/scored-mode.txt`：评分版专用附加提示词。
- `tests/`：模式、维度优先级、票据、大小和文件特征测试。

## 错误处理

- 无效模式：400，提示重新选择报告版本。
- 文件大于 10MB：413，上传前和解析前均拦截。
- 无效或过期票据：401/403，不读取 Storage 文件。
- 文件特征与格式不符：400，并删除本次上传对象。
- 评分版缺少完整五维：502，返回 `request_id`，不保存不完整报告。
- Storage 上传或下载失败：502，显示可重试提示。
- DeepSeek 断连：沿用现有 90 秒单次超时和一次受控重试。

## 验证标准

1. 默认选择普通版，旧请求不传 `report_mode` 仍正常。
2. 评分版图片一定包含综合评分、五维雷达、五项分数和判断依据。
3. 原文已有五维时保持名称；部分维度时保留并补足；无维度的 AI 转型报告才使用固定五维。
4. 10MB 以内 PDF、DOCX、TXT 可上传并解析；超过 10MB 前端和后端均拒绝。
5. 伪造扩展名、错误票据、跨邀请码票据均被拒绝。
6. 浏览器响应和日志中不出现 Service Key、签名 token 或用户 token。
7. 后台仍能下载成功解析记录的原文件和 PNG。
8. 登录页和主功能页均能看到微信联系方式。
9. `npm test`、API 语法检查、本地浏览器检查和生产部署后健康检查全部通过后才交付。
10. 桌面和手机视口下完成跨平台兼容检查；无法在本机直接运行的系统至少通过对应浏览器引擎检查，并明确说明验证边界。
11. 代码与构建产物不含真实密钥；动态内容无法注入脚本；上传伪造文件、越权票据和跨邀请码访问均被拒绝；高危依赖漏洞为零。
